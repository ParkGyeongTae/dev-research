# /commit — 점검하고, 커밋하고, 푸시한다

이 저장소는 문서 저장소다. 커밋 자체보다 **커밋 전에 문서가 앞뒤가 맞는지 확인하는 것**이 이 스킬의 본론이다.
AGENTS.md §5에 따라 커밋은 주인이 요청할 때만 하는데, **이 스킬이 호출된 것이 그 요청이다.** 따로 다시 묻지 마라.

`$ARGUMENTS`가 있으면 커밋 메시지의 힌트로 쓴다. `--no-push`가 들어 있으면 6단계를 건너뛴다.

---

## 1. 무엇이 바뀌었는지 본다

```bash
git status --short
git diff --stat
git diff --cached --stat
```

**변경이 없으면 여기서 멈추고 그렇게 말한다.** 없는 커밋을 만들지 마라.

바뀐 파일이 `docs/` 아래에 하나라도 있으면 2단계를 전부 돌린다. `.claude/`·`AGENTS.md`·설정 파일만 바뀌었다면 2단계에서 빌드만 돌리고 나머지는 건너뛴다.

이번 세션에서 네가 직접 고치지 않은 변경이 섞여 있으면 **`git diff`로 그 내용을 실제로 읽어라.** 무엇이 들어가는지 모르는 채로 커밋하지 않는다.

---

## 2. AGENTS.md §7 마무리 점검

아래를 **실제로 돌린다.** "돌렸다고 치고" 넘어가지 마라.

### (a) 문서끼리 참조하지 않았는가

```bash
grep -rn --include='*.md' '](\.\.\{0,1\}/' docs/ | grep -v 'index\.md)'
```

출력이 있으면 위반이다. **허용되는 링크는 대분류 `index.md`끼리의 참조 하나뿐**이고, `index.md`가 아닌 문서를 가리키는 링크는 어디에서도 허용하지 않는다. 링크를 지우고 **원문을 직접 확인해 그 문서 안에 내용을 적는다** — 다른 문서를 베껴 오지 않는다.

### (b) 같은 사실을 적은 다른 문서가 있는가

결론을 바꾼 커밋이면 그 주장을 쓴 다른 문서를 찾는다.

```bash
grep -rn --include='*.md' "<키워드>" docs/
```

찾았으면 **그 문서의 원문을 다시 확인해서** 고친다. 링크가 없으니 연쇄 수정은 자동으로 따라오지 않는다.

### (c) `*작성일*` 줄이 오늘 날짜인가

오늘 날짜는 세션 컨텍스트의 `# currentDate`를 먼저 쓰고, 없으면 `date +%Y-%m-%d`로 구한다. **기억으로 짐작하지 마라.**

```bash
TODAY=$(date +%Y-%m-%d)
for f in $(git diff --cached --name-only --diff-filter=ACM; git diff --name-only --diff-filter=ACM); do
  case "$f" in *.md)
    grep -Hn '^\*작성일' "$f" 2>/dev/null | grep -v "$TODAY" ;;
  esac
done
```

출력이 있으면 그 파일의 날짜가 오늘이 아니다. 고친다. 날짜는 항상 하나만 남기고, 무엇을 고쳤는지는 쓰지 않는다.

### (d) 대분류 `index.md`에 문서 목록이 생기지 않았는가

**문서 목록은 만들지 않는다.** 사이드바가 이미 목록이고, 손으로 적은 목록은 문서를 지우거나 옮기는 순간 깨진 링크나 고아 항목이 된다. 새 문서를 추가했다고 `index.md`를 손대지 마라 — 대분류의 **경계**가 애매해졌을 때만 경계 절에 한 줄 더한다.

(a)의 grep이 이것도 잡는다. 별도로 훑어보려면:

```bash
grep -n '## 문서 목록' docs/*/index.md
```

### (e) 빌드가 통과하는가

```bash
npm run build
```

`onBrokenLinks: 'throw'`이므로 **깨진 링크는 경고가 아니라 빌드 실패**다.
**빌드가 실패하면 커밋하지 않는다.** 고치고 다시 돌린다.

### (f) 확인 못 한 것이 확정처럼 남아 있지 않은가

검증 못 한 동작에는 "확인 필요", 추측에는 "추측:" 표기가 남아 있어야 한다. 이번 커밋에 들어가는 문서를 훑어 확인한다.

### (g) 실행 출력이 실제로 돌린 결과인가

지어낸 출력이 하나라도 있으면 **그 문서는 커밋하지 않는다.** 이 항목은 grep으로 안 된다 — 이번 세션에서 네가 직접 돌린 명령의 결과인지 기억을 대조한다. 확신이 없으면 그 절을 "미실행"으로 비우거나 주인에게 말한다.

## 3. 스테이징

바뀐 파일을 명시적으로 지정해서 넣는다. `git add -A`는 쓰지 마라 — 의도하지 않은 파일이 딸려 들어간다.

```bash
git add <경로들>
git status --short
git diff --cached --stat
```

`build/`·`.docusaurus/`·`node_modules/`·`.claude/settings.local.json`은 `.gitignore`에 있으므로 정상이라면 안 잡힌다. **잡혔다면 멈추고 왜인지 확인한다.**

---

## 4. 커밋 메시지

저장소 관례다. `git log -5 --format='%B'`로 최근 메시지를 보고 톤을 맞춰라.

- **한국어, 서술체(`-다`)로 쓴다.** `feat:`·`fix:` 같은 접두사는 이 저장소에서 쓰지 않는다.
- **제목 한 줄** — 무엇을 했는지. 마침표 없이.
- **빈 줄, 그리고 본문** — 왜 그렇게 했는지, 무엇을 판단했는지. 파일 목록을 나열하지 마라(그건 diff가 한다).
- 문서 커밋이면 **원문 URL·확인 날짜·실행 환경**을 본문에 적는다. 나중에 대조할 수 있어야 한다.
- 작업 중 **공식 문서만 읽으면 틀리게 이해할 지점**을 발견했으면 그것을 본문에 남긴다. 이 저장소에서 가장 값어치 있는 기록이다.
- 기존 문서의 오류를 함께 고쳤으면 **무엇이 왜 틀렸는지** 적는다.
- 2단계에서 돌린 검사가 통과했다는 사실을 마지막에 짧게 적는다.

메시지는 파일이나 heredoc으로 넘긴다. `-m` 여러 개로 이어붙이지 마라.

```bash
git commit -F - <<'EOF'
<제목 한 줄>

<본문>

검사 통과:
  grep -rn --include='*.md' '](\.\./\|](\./' docs/ | grep -v '/index\.md:'
npm run build 통과.

<트레일러>
EOF
```

**트레일러는 지어내지 마라.** 이 세션의 시스템 프롬프트가 지정한 `Co-Authored-By` / `Claude-Session` 줄을 그대로 쓴다. 세션마다 URL이 다르다.

---

## 5. 브랜치

이 저장소는 브랜치가 `main` 하나뿐이고 모든 커밋이 main에 직접 올라간다. **별도 브랜치를 만들지 않는다.**

```bash
git branch -a
git rev-parse --abbrev-ref --symbolic-full-name @{u}
```

`main`이 아닌 곳에 있다면 멈추고 주인에게 묻는다.

---

## 6. 푸시

```bash
git push origin main
git status -sb
```

`$ARGUMENTS`에 `--no-push`가 있으면 건너뛰고, 커밋만 했다고 말한다.

푸시가 거절되면(non-fast-forward) **강제 푸시하지 마라.** `git fetch && git log --oneline HEAD..origin/main`으로 무엇이 올라와 있는지 보고 주인에게 보고한다.

---

## 7. 보고

- 커밋 해시와 제목, `git push`가 출력한 `<이전>..<이후>  main -> main` 줄
- 파일 수와 증감 줄 수
- **2단계에서 돌린 검사 중 통과한 것과 건너뛴 것을 구분해서** 말한다
- 점검에서 고친 것이 있으면 무엇을 고쳤는지

검증 없이 넘어간 항목이 있으면 숨기지 말고 그렇게 말한다.
