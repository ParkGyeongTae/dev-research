# 아이디어

**앱·웹 또는 둘 다로 개발해 출시할 제품 아이디어**를 모으고 구체화하는 곳입니다. 떠오른 생각부터 검증 결과와 출시 여부에 대한 판단까지 다룹니다.

## 다루는 것

- 문제와 대상 사용자 — 누가 어떤 상황에서 불편을 겪는지, 지금은 어떻게 해결하는지
- 제품의 가치 — 어떤 도움을 주려는지, 기존 대안과 무엇이 다른지
- 최소 기능과 개발 범위 — 첫 출시에서 해결할 문제와 뒤로 미룰 기능
- 제공 형태 — 웹·앱·둘 다 중 무엇으로 시작할지와 그 선택의 이유
- 검증과 출시 판단 — 사용자 반응, 수익 모델 가설, 실험 결과, 진행·보류·중단 이유

## 어디로 가는가

- **특정 제품을 왜 만들고 무엇부터 검증할지**는 여기에 둡니다. 기술별이 아니라 아이디어별 폴더로 묶고, 문서 하나는 질문 하나에 답합니다.
- **수요·차별점·수익성에 관한 예상**은 검증 전까지 가설로 적습니다. 직접 관찰한 사실, 외부 자료, 자신의 판단을 구분하며 검증 결과가 생기면 그 근거를 함께 남깁니다.
- **특정 제품에서 웹·앱을 선택한 이유나 기능 범위를 정한 판단**도 여기에 둡니다. 아직 정하지 않은 플랫폼이나 기능을 미리 확정할 필요는 없습니다.
- **브라우저 UI·렌더링·상태 관리처럼 기술 자체의 동작**을 조사한 내용은 [프론트엔드](../frontend/index.md)로 갑니다.
- **서버·API·인증처럼 서버 기술 자체의 동작**을 조사한 내용은 [백엔드](../backend/index.md)로 갑니다.
- **배포 환경·클라우드·관측성 자체의 동작**을 조사한 내용은 [인프라](../infrastructure/index.md)로 갑니다.
