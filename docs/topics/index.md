# 기술 리서치

**기술 하나를 깊이 판 문서 묶음**입니다. 기술 하나가 폴더 하나이고, 폴더 안에는 채워야 할 칸이 정해져 있습니다.

칸을 미리 정해 둔 이유는 두 가지입니다. 하나는 매번 "무엇부터 쓸지" 고민하지 않기 위해서고,
다른 하나는 **비어 있는 칸이 곧 모르는 부분**이라 학습의 다음 목표가 저절로 드러나기 때문입니다.

## 카테고리

| 폴더 | 다루는 것 |
| --- | --- |
| `data-engineering/` | 스트리밍·배치 처리, 오케스트레이션, 데이터 포맷·레이크하우스 (Kafka, Spark, Airflow, Iceberg …) |
| `database/` | 관계형·NoSQL·분석용 데이터베이스의 내부 동작과 튜닝 (PostgreSQL, ClickHouse, Redis …) |
| `backend/` | 애플리케이션 서버, API, 런타임 (Spring, FastAPI, JVM, gRPC …) |
| `infrastructure/` | 컨테이너·오케스트레이션·클라우드·IaC·관측성 (Kubernetes, Terraform, Prometheus …) |
| `cs/` | 위 어디에도 속하지 않는 기반 지식 중 **제품 하나를 깊이 판 형태**의 것 |

카테고리는 필요할 때 늘립니다 — 폴더를 만들면 내비게이션에 자동으로 잡힙니다.
새 기술 폴더를 만드는 절차는 [작성 규칙](../authoring/authoring-guide.md)에 있습니다.

## 문서 구성

| 파일 | 답해야 할 질문 |
| --- | --- |
| `00_summary.md` | 다른 문서를 열지 않고도 이 기술의 그림이 서는가 |
| `01_overview.md` | 이 기술은 **어떤 문제**를 풀려고 나왔고, 없던 시절엔 어떻게 했는가 |
| `02_architecture.md` | 내부는 어떤 구성 요소로 나뉘고, 요청 하나가 어떤 경로로 흐르는가 |
| `03_concepts.md` | 이 기술을 이해하려면 반드시 알아야 하는 개념은 무엇인가 |
| `04_hands-on.md` | 직접 돌려본 기록 — 재현 가능한 설정·명령·결과 |
| `05_operations.md` | 실무에서 어떻게 배포·모니터링·튜닝하는가 |
| `06_pitfalls.md` | 어디서 사람들이(그리고 내가) 틀리는가 |
| `07_references.md` | 근거로 쓴 1차 자료는 무엇인가 |

해당 없는 파일은 **왜 해당 없는지 한 줄 남기고 뺍니다** — 빈 껍데기 문서를 남기지 않습니다.
