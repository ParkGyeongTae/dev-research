# 용어집

이 사이트 전반에서 쓰는 용어의 정의를 모았습니다. **두 개 이상의 문서에서 쓰는 용어만** 여기에 올리고,
한 기술에서만 쓰는 용어는 그 기술 폴더의 `03_concepts.md`에 둡니다.

용어를 새로 쓸 일이 생기면, 문서 안에서 즉석으로 정의하지 말고 **먼저 이 문서를 갱신합니다** —
같은 말이 문서마다 다른 뜻으로 쓰이는 것을 막기 위해서입니다.

한 문단으로 설명이 안 되는 개념은 여기에 한 줄 정의만 두고 [개념 정리](./concepts/index.md)로 넘깁니다.

---

## 데이터 처리

**멱등성 (idempotency)**
: 같은 연산을 여러 번 실행해도 결과가 한 번 실행한 것과 같은 성질. 분산 시스템에서 재시도는 피할 수 없으므로, 재시도가 안전하려면 연산이 멱등해야 합니다. "같은 키로 덮어쓰기"는 멱등하고, "카운터 1 증가"는 멱등하지 않습니다.

**정확히 한 번 (exactly-once)**
: 메시지가 정확히 한 번만 처리된 것과 **같은 결과**를 보장하는 것. 네트워크상에서 메시지를 물리적으로 한 번만 전달하는 것은 불가능하므로, 실제 구현은 "최소 한 번 전달 + 중복 제거" 또는 "트랜잭션"으로 같은 효과를 냅니다 — 이름과 구현이 다르다는 점이 오해의 출발점입니다.

**최소 한 번 / 최대 한 번 (at-least-once / at-most-once)**
: 각각 유실은 없지만 중복이 생길 수 있는 보장, 중복은 없지만 유실이 생길 수 있는 보장. 대부분의 스트리밍 시스템의 기본값은 최소 한 번입니다.

**백프레셔 (backpressure)**
: 소비자가 생산자의 속도를 따라가지 못할 때, 생산 속도를 늦추도록 역방향으로 신호를 보내는 것. 백프레셔가 없으면 버퍼가 무한히 쌓이다 메모리 부족으로 끝납니다.

**이벤트 시각 vs 처리 시각 (event time vs processing time)**
: 사건이 **실제로 일어난 시각**과 시스템이 그 사건을 **처리한 시각**. 둘은 네트워크 지연·재처리·장애 복구 때문에 항상 벌어지며, 어느 쪽을 기준으로 집계하느냐가 결과를 바꿉니다.

**워터마크 (watermark)**
: "이 시각 이전의 이벤트는 (거의) 다 도착했다"고 시스템이 판단하는 기준선. 늦게 도착하는 이벤트를 언제까지 기다릴지 정하는 장치이며, 늦게 잡으면 지연이 늘고 빨리 잡으면 데이터가 누락됩니다.

**CDC (Change Data Capture)**
: 데이터베이스의 변경 이력(주로 트랜잭션 로그)을 읽어 다른 시스템으로 전파하는 방식. 주기적으로 전체를 다시 읽는 방식보다 부하가 작고 지연이 짧습니다.

**백필 (backfill)**
: 파이프라인 로직이 바뀌거나 장애를 복구할 때, 과거 기간의 데이터를 다시 계산해 채워 넣는 작업.

## 저장과 일관성

**최종 일관성 (eventual consistency)**
: 새로운 쓰기가 없다면 언젠가는 모든 복제본이 같은 값에 수렴한다는 보장. "언젠가"가 언제인지는 보장하지 않으므로, 방금 쓴 값을 바로 읽으면 옛 값이 나올 수 있습니다.

**WAL (Write-Ahead Log)**
: 데이터 파일을 고치기 **전에** 변경 내용을 먼저 순차 기록하는 로그. 장애 시 이 로그로 복구하며, 순차 쓰기라 임의 쓰기보다 빠릅니다. 데이터베이스의 복구·복제·CDC가 모두 여기에 얹혀 있습니다.

**파티셔닝 / 샤딩 (partitioning / sharding)**
: 데이터를 키 기준으로 여러 조각으로 나누는 것. 보통 파티셔닝은 한 시스템 안에서의 분할, 샤딩은 여러 노드로의 분산을 가리키지만 경계가 엄격하진 않으므로 **문서마다 어느 뜻인지 밝혀 씁니다**.

**컬럼너 포맷 (columnar format)**
: 같은 컬럼의 값을 모아 저장하는 파일 형식(Parquet, ORC 등). 일부 컬럼만 읽는 분석 질의에서 I/O가 크게 줄고 압축률이 높지만, 한 행 전체를 자주 읽고 쓰는 작업엔 불리합니다.

**스키마 진화 (schema evolution)**
: 이미 쌓인 데이터를 다시 쓰지 않고 스키마를 바꾸는 것. 옛 코드가 새 데이터를 읽을 수 있으면 전방 호환, 새 코드가 옛 데이터를 읽을 수 있으면 후방 호환이라 부릅니다.

## 운영

**지연시간 / 처리량 (latency / throughput)**
: 요청 하나가 끝나는 데 걸리는 시간과, 단위 시간당 처리한 요청 수. 둘은 대개 **맞바꾸는 관계**라 배치 크기를 키우면 처리량이 오르고 지연시간도 같이 오릅니다.

**p50 / p95 / p99 (백분위 지연시간)**
: 요청을 지연시간 순으로 줄 세웠을 때 각각 50%·95%·99% 지점의 값. 평균은 소수의 느린 요청에 가려지므로 성능 논의는 백분위로 합니다.

**SLI / SLO / SLA**
: 측정하는 지표(SLI), 그 지표에 대해 스스로 정한 목표(SLO), 외부와 맺은 계약과 위반 시 책임(SLA). 셋을 뭉뚱그려 쓰면 "목표"와 "약속"이 섞입니다.

**관측성 (observability)**
: 시스템 외부에서 얻는 신호(메트릭·로그·트레이스)만으로 내부 상태를 추론할 수 있는 정도. 미리 정해 둔 질문에 답하는 모니터링과 달리, **예상하지 못한 질문**에 답할 수 있는지를 봅니다.
