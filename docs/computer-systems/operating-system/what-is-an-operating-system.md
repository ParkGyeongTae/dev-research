# 운영체제란 무엇인가 — 프로그램이 컴퓨터 자원을 사용하는 실행 환경

> **원문** — [Operating System, NIST CSRC Glossary](https://csrc.nist.gov/glossary/term/Operating_System)
>
> **확인 날짜** — 2026-09-11. 용어집이 인용하는 여러 정의 중 NIST SP 800-152의 정의와 NIST SP 800-44의 설명을 대조했습니다.
>
> **검증 상태** — NIST 공식 용어집을 읽고 정리했습니다. macOS에서 확인한 실행 환경과 명령 출력도 포함했지만, 운영체제의 모든 구성 요소를 직접 검증한 문서는 아닙니다.

운영체제는 **프로그램이 CPU·메모리·저장 장치·네트워크 같은 컴퓨터 자원을 사용할 수 있게 하는 소프트웨어 층**입니다. 프로그램마다 하드웨어를 직접 제어하게 두면 서로의 메모리를 침범하거나 저장 장치를 동시에 망가뜨릴 수 있으므로, 운영체제가 공통 규칙과 접근 경계를 제공합니다.

NIST는 운영체제를 하나의 실행 프로그램으로만 보지 않고, 다른 프로그램이 실행될 수 있는 기반으로 설명합니다.

> A collection of software that manages computer hardware resources and provides common services for computer programs.
>
> **번역** — 컴퓨터 하드웨어 자원을 관리하고 컴퓨터 프로그램에 공통 서비스를 제공하는 소프트웨어의 모음입니다.
>
> — [Operating System, NIST CSRC Glossary](https://csrc.nist.gov/glossary/term/Operating_System) (확인: 2026-09-11)

여기서 중요한 단어는 `manages`와 `common services`입니다. 운영체제는 단순히 부팅할 때 한 번 실행되는 프로그램이 아니라, 실행 중인 프로그램들이 자원을 요청할 때 그 요청을 중재하고 공통 기능을 제공합니다.

## 운영체제와 커널은 같은 말이 아닙니다

커널은 운영체제의 핵심 부분이지만 운영체제 전체와 같은 말은 아닙니다. 커널 외에도 셸, 시스템 유틸리티, 서비스, 라이브러리, 장치 관리 프로그램 등이 운영체제 환경을 구성합니다.

```text
응용 프로그램
  ↓ 파일·프로세스·네트워크 기능 요청
라이브러리와 시스템 인터페이스
  ↓
커널
  ↓
장치 드라이버
  ↓
하드웨어
```

이 구조 때문에 프로그램은 디스크의 물리적 섹터나 메모리 칩을 직접 다루지 않고 `open()`, `read()`, 프로세스 생성 같은 운영체제 인터페이스를 사용합니다. 운영체제는 요청자의 권한과 자원 상태를 확인한 뒤 허용된 작업만 수행합니다.

## 가장 작은 사례: 파일 읽기

셸에서 다음 명령을 실행한다고 하겠습니다.

```sh
cat input.txt
```

`cat`은 파일을 열고 읽은 뒤 표준 출력에 씁니다. 프로그램 관점에서는 파일 경로를 넘겨 읽기를 요청하지만, 실제 저장 장치 접근과 권한 검사는 커널이 맡습니다. 파일이 없거나 읽기 권한이 없으면 운영체제가 실패를 보고하고 `cat`은 그 결과를 사용자에게 보여 줍니다.

따라서 “프로그램이 파일을 읽는다”는 말은 하드웨어를 직접 조작한다는 뜻이 아니라, **운영체제가 제공하는 파일 추상화에 요청을 보내고 운영체제가 대신 장치에 접근한다**는 뜻입니다.

## 이 컴퓨터에서 확인한 실행 환경

아래는 이 문서를 작성한 macOS 환경에서 직접 실행한 결과입니다.

```text
$ uname -a
Darwin gyeongtaee.local 24.6.0 Darwin Kernel Version 24.6.0: Mon Jan 19 22:01:58 PST 2026; root:xnu-11417.140.69.708.3~1/RELEASE_ARM64_T6041 arm64

$ sw_vers
ProductName:            macOS
ProductVersion:         15.7.4
BuildVersion:           24G517
```

이 출력으로 확인할 수 있는 것은 이 환경이 macOS 15.7.4이고 Darwin 커널 24.6.0을 사용한다는 사실입니다. 이것만으로 macOS의 모든 운영체제 구성 요소나 모든 POSIX 기능이 같은 방식으로 구현되었다고 결론 내릴 수는 없습니다.

운영체제에 대한 설명은 커널만 설명하는 것보다 넓어야 합니다. 반대로 커널의 프로세스 스케줄링이나 가상 메모리 구현을 설명할 때는 운영체제 전체가 아니라 커널이라는 기술에 초점을 맞춰야 합니다.
