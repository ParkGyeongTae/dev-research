# Codex 베스트 프랙티스

> **원문** [Best practices](https://learn.chatgpt.com/guides/best-practices) (learn.chatgpt.com/guides/best-practices)<br/>
> 부제 *"Getting started with Codex and proven practices for better results"*<br/>
> **확인 날짜** 2026-09-05 — 원문에 판번호도 최종 수정일 표기도 없습니다<br/>
> **검증 상태** 원문을 읽고 정리한 문서입니다. **Codex를 직접 써보지 않았습니다** — 아래 내용은 전부 원문에서 읽은 것이고, 동작을 재현해 확인한 것은 하나도 없습니다.

:::warning 이 문서의 정확도 한계
원문 전문을 그대로 받아오지 못했고(저작권 사유로 재현 거절), **섹션별 설명 형태로 받은 자료를 근거로 정리했습니다.** 그래서 명령 이름·경로·플래그 같은 세부는 원문과 어긋날 수 있습니다. 실제로 쓰기 전에 원문에서 대조하세요.
:::

## 대상 범위

Codex는 하나의 인터페이스가 아닙니다. 원문은 **CLI, IDE 확장, ChatGPT 데스크톱 앱**을 아우르는 Codex 전반을 다룹니다. 그래서 아래 권장 중 일부는 특정 인터페이스에만 존재합니다(예: 예약 작업은 데스크톱 앱 기능).

---

## 1. 프롬프트의 네 요소

원문이 첫 항목으로 두는 건 프롬프트 구조입니다. 네 가지를 넣으라고 합니다.

| 요소 | 무엇을 쓰는가 |
| --- | --- |
| **Goal** | 무엇을 바꾸거나 만들 것인가 |
| **Context** | 어떤 파일·폴더·문서·예시가 필요한가 (`@` 멘션으로 지정) |
| **Constraints** | 따라야 할 표준·아키텍처·안전 요구사항 |
| **Done when** | 무엇이 되면 끝인가 — 테스트 통과, 동작 변경, 버그 해결 |

근거는 명확합니다 — 범위가 분명하면 **추측이 줄고 검토하기 쉬운 결과물**이 나옵니다.

네 번째 항목인 **Done when이 핵심**입니다. 완료 조건을 프롬프트에 못 박는다는 건, 에이전트가 "다 된 것 같다"로 멈추지 못하게 만든다는 뜻입니다.

추론 강도는 **Low / Medium / High / Extra High**로 조절할 수 있고, 음성 받아쓰기도 지원한다고 합니다.

## 2. 어려운 작업은 계획 먼저

복잡하거나 모호한 작업은 코딩 전에 계획 단계를 거치라고 합니다. 근거는 **계획 없이 시작하면 방향을 잃거나 재작업하게 된다**는 것입니다.

- plan mode 토글 — `/plan` 또는 `Shift+Tab`
- Codex가 먼저 **질문하게** 시키는 방법
- `PLANS.md` 템플릿

## 3. `AGENTS.md`로 지침을 재사용한다

매번 반복하는 설명을 저장소의 `AGENTS.md`에 넣으라고 합니다. 넣을 항목이 구체적으로 나열돼 있습니다.

- 저장소 레이아웃과 중요한 디렉터리
- 프로젝트 실행 방법
- 빌드·테스트·린트 명령
- 엔지니어링 관례와 PR 기대치
- 제약과 **금지 사항**
- **완료의 정의와 검증 방법**

계층 구조를 지원합니다 — `~/.codex/AGENTS.md`가 개인 기본값, `.codex/AGENTS.md`가 저장소 수준입니다. `/init`으로 템플릿을 만듭니다.

:::tip 이 저장소와 바로 맞물리는 지점
이 저장소는 이미 루트에 [`AGENTS.md`](https://github.com/ParkGyeongTae/dev-research/blob/main/AGENTS.md)를 두고 `CLAUDE.md`를 그 심볼릭 링크로 걸어두었습니다. 같은 파일 이름을 Codex도 쓴다는 뜻이라, **한 파일로 두 에이전트를 동시에 다룰 수 있습니다.**

다만 원문이 말하는 경로는 `.codex/AGENTS.md`(저장소 수준)이고 루트 `AGENTS.md`와 같은 것인지는 **확인 필요**입니다.
:::

## 4. `config.toml`로 기본값을 고정한다

모델 선택, 추론 수준, 샌드박스 모드, 승인 정책을 매번 손으로 맞추지 말고 설정으로 굳히라고 합니다.

| 경로 | 범위 |
| --- | --- |
| `~/.codex/config.toml` | 개인 기본값 |
| `.codex/config.toml` | 저장소별 동작 |
| `$CODEX_HOME/profile-name.config.toml` | 프로필별 오버라이드 |

핵심 제어 두 가지는 **승인 모드**(언제 명령 실행 권한을 물을 것인가)와 **샌드박스 모드**(파일 접근 범위)입니다.

## 5. 테스트와 리뷰로 신뢰성을 올린다

테스트 작성 → 검사 실행 → 결과 확인 → 코드 리뷰를 **한 루프로** 시키라고 합니다. 체크리스트는 테스트 작성/갱신, 린트·포맷·타입 검사, 최종 동작 확인, 버그·회귀·위험 패턴 리뷰입니다.

- `/review` — 대화형 리뷰. base 브랜치·커밋·커스텀 지침을 지정할 수 있습니다
- GitHub 통합으로 PR 자동 리뷰
- 팀 리뷰 기준은 `code_review.md`에 쓰고 `AGENTS.md`에서 참조

## 6. MCP로 저장소 밖 맥락을 가져온다

MCP 서버를 붙일 조건이 네 가지로 정리돼 있습니다.

- 필요한 데이터가 **저장소 밖**에 있을 때
- 데이터가 **자주 바뀔** 때
- 지침을 복사해 넣는 대신 **도구를 쓰고 싶을** 때
- 여러 프로젝트에서 **같은 통합이 반복될** 때

설정은 데스크톱 앱의 `Settings > MCP servers`, CLI는 `codex mcp add`입니다.

## 7. 반복 작업을 스킬로 만든다

반복 워크플로를 `SKILL.md`로 정의합니다. 좋은 스킬의 조건이 명시돼 있습니다.

- **한 가지 일만** 한다 (단일 책임)
- 입력·출력이 분명하다
- **언제 쓰는지**를 설명에 적는다
- 사용자가 실제로 말할 법한 **트리거 문구**를 넣는다

저장 위치는 개인이 `$HOME/.agents/skills`, 팀이 저장소 안 `.agents/skills`입니다. `$skill-creator` 스킬로 첫 버전을 만들고, 다듬어지면 플러그인으로 발전시킵니다.

판정 기준이 하나 있습니다 — **같은 프롬프트를 세 번 이상 쓰고 있으면** 스킬로 만들 때입니다.

## 8. 안정된 워크플로는 예약 작업으로

데스크톱 앱의 **Scheduled** 페이지에서 정기 실행을 겁니다. 프로젝트·프롬프트·주기·실행 환경(git worktree 또는 로컬)을 지정합니다.

후보로 제시되는 것: 최근 커밋 요약, 버그 스캔, 릴리스 노트 작성, CI 실패 확인, 스탠드업 요약, 정기 분석.

역할 분담이 깔끔합니다 — **스킬은 "어떻게"를, 예약 작업은 "언제"를 정의합니다.**

## 9. 긴 대화를 관리한다

원칙은 **대화 하나 = 응집력 있는 작업 하나**입니다. 근거는 컨텍스트 오염이 누적되면 품질이 떨어진다는 것.

| 명령 | 하는 일 |
| --- | --- |
| `/resume` | 저장된 대화 재개 |
| `/fork` | 기존 기록을 유지한 채 분기 |
| `/compact` | 긴 대화 요약 |
| `/agent` | 서브에이전트 전환 |
| `/status` | 현재 세션 상태 |

병렬로 돌릴 일(탐색, 테스트, 분류)은 서브에이전트로 보냅니다.

## 원문이 밝히는 경계 — "Common mistakes"

이 페이지도 권장만 싣지 않습니다. 마지막 절이 통째로 실수 목록이고, **각 항목에 왜 문제인지가 붙어 있습니다.**

| 실수 | 왜 문제인가 |
| --- | --- |
| 모든 지침을 프롬프트에 담기 | 매번 반복 입력, 유지보수 불가 — `AGENTS.md`로 중앙화 |
| 빌드·테스트 명령을 안 알려주기 | Codex가 검증을 못 함 → 틀린 결과를 그대로 내보냄 |
| 복잡한 작업에 계획 단계 생략 | 방향 오류와 재작업 반복 |
| **성급하게 전체 권한 부여** | 파일 손상·보안 위험. **신뢰가 쌓이는 만큼만 점진적으로 넓힌다** |
| **git worktree 없이 실제 파일에서 반복 작업** | 작업 충돌과 데이터 손실 |
| **수동으로 못 믿는 작업을 예약 걸기** | 실패한 자동화가 쌓임. 수동 검증이 먼저 |
| 단계마다 지켜보며 쓰기 | 사람 시간 낭비 — 병렬로 돌려야 함 |
| 프로젝트 전체를 대화 하나로 | 컨텍스트 팽창, 토큰 낭비, 품질 저하 |

굵게 표시한 셋이 특히 **순서에 대한 경고**입니다. 권한 확대도, 예약 자동화도 **먼저 손으로 믿을 수 있게 된 다음**에 하라는 것입니다.

## 읽고 든 판단

여기부터는 **원문에 있는 말이 아니라 정리하며 든 생각**입니다.

- **Claude Code 문서와 겹치는 항목이 놀랄 만큼 많습니다** — `AGENTS.md`(파일 이름까지 동일), plan mode, MCP, 스킬(`SKILL.md`), 서브에이전트, `/compact`, 권한/샌드박스. 도구를 고르는 문제가 아니라 **에이전틱 코딩 자체의 공통 문법이 굳어지고 있다**고 읽는 게 맞아 보입니다.
- **다른 점은 강조하는 축입니다.** Claude Code 문서가 *컨텍스트 윈도우*라는 단일 제약에서 모든 권장을 끌어냈다면, 이 문서는 *반복되는 마찰을 자산으로 굳히는 것*(AGENTS.md → 스킬 → 예약 작업 → 플러그인)에 무게를 둡니다. 같은 조언도 이유가 다릅니다.
- **예약 작업은 이 둘 중 Codex에만 있는 축입니다.** "언제 돌 것인가"를 도구가 직접 관리한다는 건 무인 운영을 전제한다는 뜻이고, 그래서 "수동으로 믿을 수 있기 전에 예약하지 마라"가 강한 경고로 붙어 있습니다.

## 확인하지 못한 것

- **전부입니다.** Codex를 설치해 돌려본 적이 없습니다. 명령·경로·플래그가 현재 버전과 맞는지 확인하지 않았습니다.
- 원문 전문을 확보하지 못해(재현 거절), 섹션 설명 자료를 근거로 정리했습니다. **표현과 세부가 원문과 다를 수 있습니다.**
- 루트 `AGENTS.md`와 `.codex/AGENTS.md`의 관계 — 같은 파일을 가리키는지, 별개인지 **확인 필요**
- 원문에 판번호·최종 수정일이 없어 **어느 버전 기준인지 알 수 없습니다.**
